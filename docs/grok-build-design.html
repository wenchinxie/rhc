0一則訊息怎麼走完

使用者一則訊息進 的 handle_prompt 之後，走的是下面這張圖。2026-08-29 讀碼

壓縮與（粗筆）　取樣後三路　左側回頭邊是還有工具、再進

  1. 入口。handle_prompt 把使用者訊息寫進 transcript，再開外層迴圈。
  2. 每輪取樣前。必要時先壓縮，再組送給模型。預設 85% 觸發，見 §5。
  3. 取樣後三路。無工具：內層收工。有工具：執行、寫回、回頭再取樣。同一工具連打：本輪硬停。
  4. 外層。Stop hook 可再推；滿 8 次就停，不再問 hook。

圖由 dag_grammar.py 排出。迴圈順序讀自 turn.rs handle_prompt 與 process_conversation_turn，2026-08-29。

1三種入口接到同一個 MvpAgent

全螢幕終端、grok -p 一問一答、grok agent stdio 只換 ACP 位元組怎麼送到同一個 ；每個對話仍是 。2026-08-29 組裝根是 xai-grok-pager-bin 的 main：它起非同步 runtime、更新策略、再分派，自己不跑取樣迴圈。

入口誰在說話接到哪
互動全螢幕 grokpager 當 ACP 用戶端行程內 spawn_grok_shell，或 Unix 插座連獨立 leader（失敗則退回行程內）
一問一答 grok -ppager headless.rs一律行程內 spawn_grok_shell，不走 leader
grok agent stdio / leader / serveshell agent/app.rs本地 ，或當 leader 的 JSON / WebSocket 橋

Leader 是長駐行程（檔案鎖加 ~/.grok/ 下的插座），讓多個全螢幕終端共用一個 。workspace 套件管檔案系統、權限、checkpoint，給 用，不是第三種入口。

第一次取樣之前要齊的是：有效設定、認證（瀏覽器登入或 API key）、組織下發的設定閘、模型目錄、ACP initialize、再開 new_session 生 。

README Repository layout；pager-bin/src/main.rs；shell agent/app.rs。

2Agent 進迴圈前一次組好提示、工具與權限

進迴圈前，AgentBuilder 一次組好 system prompt、、權限模式。crate README 寫這個物件可攜；結構註解寫它綁在該次對話。以結構為準：組好後帶已渲染 system prompt、、reminder 與 compaction 政策。

預設 promptMode 是 Extend：底座模板（主代理 prompt.md，子代理 subagent_prompt.md）再接定義 body。Full 才把 body 當整份 system prompt。

AGENTS.md 變成使用者前綴裡的 <system-reminder>，系統提示仍用底座模板。發現到的檔案列在 agents_md_files。檔案開頭的 YAML 點名的 skills 前置進 prompt_body；其餘 skill 清單進對話上下文給執行期發現。

抽出套件時的決定Agent 從 xai-grok-shell 抽成一等型別，讓全螢幕終端以外的入口也能組同一份物件。抽完仍經 綁對話，所以不能序列化到另一個行程當「同一份 Agent」用。

xai-grok-agent/src/agent.rs、builder.rs、prompt/context.rs；crate README。

3兩層迴圈跑完一則訊息

一則使用者訊息在 裡有兩層迴圈，外面還有 actor 收命令。2026-08-29 是 process_conversation_turn；外層在 handle_prompt 裡呼叫它，再跑 。

層函式何時停
actorrun_sessionShutdown、頻道關
外層handle_prompt 的 loop內層不是 Completed，或 回 AllowStop
內層process_conversation_turn模型沒叫工具、同一工具連打硬停、或 max_turns

外層每次先跑 process_conversation_turn_with_recovery。若 goal 仍要 Continue，注入指令再進內層。否則 run_stop_gate：AllowStop 結束；KeepWorking 把 hook 回饋推進 transcript，續跑計數加一。

續跑上限 8 次，常數 MAX_STOP_HOOK_CONTINUATIONS_PER_TURN。碼裡沒寫是誰定的。人工選的常數改它要重測回合結束腳本：滿 8 次時連腳本都不叫，直接 AllowStop。 行程結束腳本另有 5 秒預算。人工選的逾時改它的成本是重測關行程會不會被這段腳本卡住；逾時就放行。

每一圈：注入 reminder 與記憶、必要時壓縮、組請求、、送給模型。模型若回「先壓縮再重送」，這一圈 continue。沒有 tool calls 才收工；有則 execute_tool_calls，結果寫回再取樣。

同一工具連打走硬停，不經 。權限拒絕則本輪標成取消。

turn.rs handle_prompt / process_conversation_turn；stop_gate.rs。

4模型工具清單固定，外部工具用兩支名字

每輪送給模型的是 的 tool_definitions_builtins_only()，再加計畫模式過濾。名稱帶 __ 的外部伺服器工具走 search_tool，留在 builtins_only 之外。

search_tool 用關鍵字檢索在 ToolIndex 上找外部伺服器工具並回 schema。use_tool 依 server__tool 名字派發。

search_tool / use_tool 分成兩支
機制

模型永遠看到同一組內建工具加上這兩支固定名字的工具。要呼叫外部伺服器時先 search 再 use。use_tool 走內部派發，避開外層 鎖。

前提

模型對固定前綴做快取；工具名一變，快取失效。外部伺服器會在對話中途增減。

適配

Grok 的外部伺服器可在對話中掛上。註解寫明：工具清單跨輪穩定，新工具被發現時不改模型看到的工具名。

不抄

外部工具只經 search_tool 與 use_tool 進模型。若把本機工具名誤打進 use_tool，預設回「直接呼叫」的糾正錯誤；離線評估可關掉這條糾正。

內建實作在 implementations/grok_build/。另有 openai/codex 與 sst/opencode 的埠，NOTICE 寫在 tools 套件。分類表只給 kind 與標籤；哪一支進清單由 Agent preset 決定。

sampler_turn.rs:214-219；search_tool/mod.rs；use_tool/mod.rs:80-82；xai-grok-tools/THIRD_PARTY_NOTICES.md。

5壓縮在取樣前觸發，梯子最後一階非空

壓縮在取樣前觸發，最後一階必須交出非空結果。計量是估計 token（上次模型回報的 total_tokens，加上之後位元組差除以 4）。門檻預設 85%：used * 100 >= window * pct。85 在沒有 env、使用者設定、遠端覆寫時才用，與 Grok 網頁聊天共用。人工預設改它的成本是重測何時開始把舊對話收成摘要。

寫在 fit.rs 檔頭，順序不可重排。後一階只在前面跑完仍超標時才跑。

階做什麼何時跑
0 Verbatimhistory 加 steps 已在預算內永遠先量
1 HistoryTurnSelected丟最舊的歷史輪，盡量留 steps0 仍超
2 ToolTruncated截過長工具結果；預算位元組 = token × 4，不做二分搜1 仍超
3 StepTurnsSelected丟最舊的 step 輪2 仍超
4 Emergency硬縮最新一則3 仍超；這一階必須非空

token × 4 來自 xai-token-estimation::BYTES_PER_TOKEN = 4，是位元組近似，不是再 tokenize 迴圈。跨 session 的記憶寫在 ~/.grok/memory/；壓縮前會先 flush。transcript 追加到該 session 目錄的 chat_history.jsonl，壓縮時整份替換。

固定梯子，最後一階總產出
機制

五階依序；後階只在仍超標時跑。Emergency 測試要求最新一則留下，計畫不得為空。

前提

steps 比舊聊天歷史更值得留。一次位元組近似對下游夠用。

適配

空的最後一階計畫曾中止「上下文太長」之後的恢復，所以最後一階必須交出非空。觸發接在取樣前，與 Grok 網頁聊天共用同一份 core 套件。

不抄

截斷用一次位元組近似，梯子順序固定。下游若硬拒超標，這一階近似就要改成精確計數。

turn.rs:2131-2133；code_compaction/config.rs:13；intra_compaction/fit.rs；chat_persistence.rs。

6子代理與批次腳本有預算，規則命中的 Ask 要人點頭

子代理與批次腳本有呼叫次數上限；規則命中的 Ask 維持要人點頭。子代理由父 用 parent_session_id 登記；再往下生的會接到根。隔離預設 none；worktree 才走 xai_fast_worktree::WorktreeBuilder。同一對話同時跑的子代理預設 32，到上限預設排隊。人工預設 DEFAULT_MAX_CONCURRENT改它的成本是重測同對話排隊延遲。

workflow 用 Rhai 腳本引擎。journal 重放要序號、種類、請求雜湊全中，否則當失敗。child-agent 預算預設 128、上限 1024；現場同時跑的子代預設 32。人工預算改 128 或 1024 的成本是重測 workflow 會不會在半路 Pause。

goal 分類器每輪上限預設 10，註解寫這是 runaway 後門；主停是連續 2 次相同缺口指紋。人工選的次數改 10 或 2 的成本是重測 goal 何時被強制停、會不會誤停。

規則命中的 Ask 不讓模型放行
機制

gate_preflight 分開 rule-match Ask 與 fail-closed Ask。只有後者、且在 auto mode、且不是 rule-match 時，才 defers_gate_ask 給分類器。

前提

政策規則比模型判斷穩定。拆不開的命令才需要分類器。

適配

註解原文：rule-match Ask stays a prompt，never waived by a model。測試寫 model verdict must never waive a matched policy rule。

不抄

真實政策命中維持要人點頭。規則太吵該改規則，不該讓模型放行。

沙箱用 / （feature enforce）。行程級網路維持開著，因為要打模型 API；Linux 子行程斷網走 ，且要 applied、configured、Linux 三條件同時成立。 看的是請求的非 off 設定檔，不是 is_active()。 Linux 上必要保護沒套上且不在 裡，shell 拒開。

gate_preflight.rs:50-52；xai-grok-sandbox/src/lib.rs；xai-workflow/src/lib.rs；goal_tracker.rs:20；admission.rs:6。
