summary

掛上東西時記下怎麼拆。料不齊就不動手。料被拿走，先拆靠它的人。

feynman

想像一塊共用掛板。一個工位把釘子釘上去，掛燈、掛尺。工位收攤時必須拔自己釘的釘子，燈才不會留在別人板上。開工前要看鑽孔機在不在板上；鑽孔機被拿走，這個工位先停、先拔釘，再讓鑽孔機離開。論文把「拔釘」做成每次改掛板都帶回來的拆法，把「等鑽孔機」做成掛板一變就通知工位。

論文做的是把卸載與依賴做成 runtime 保證

靜態組合在編譯期定案：函式呼叫、import、繼承。動態組合要在跑的時候掛上、卸下、改設定。作業系統用重啟行程換時間軸；容器編排器用服務邊界換空間軸。論文說這兩層太粗：重啟丟掉行程內快取與進行中工作，容器又表達不了同一位址空間裡的依賴。

VS Code 是反例。Marketplace 2026-06-09：安裝數前 100 個擴充裡，87 個有可執行碼，卸載要重啟 extension host；只有 7 個對非內建擴充宣告 extensionDependencies。擴充靠主機提供的 command／view，彼此幾乎不宣告依賴。

古典 effect／coeffect 是編譯期註解。這篇把它們 reify 成跑得動的 Context 型別。

時間軸：每次改掛板都留下拆法

一個副作用是 Γ → Γ × (Γ → Γ)：改現況，並交出拆法。拆法只保證在「它剛改完的那個狀態」還原，不是任意狀態都行。

掛板旁邊放一個累積器 φ。每做一次改動，就把這次的拆法接上去。全部拆完等於從頭沒掛過（Theorem 7）。同一工位自己的釘子，後掛的先拔（Theorem 16，LIFO）。

兩個工位的釘子要能交錯拔，論文多要一個條件：（Definition 19）。兩邊的改動要可交換，而且不能改壞對方交出來的拆法。這個條件不自動成立。做不到就退回兩條較弱的路：同一工位仍 LIFO；跨工位靠共效規格排卸載順序。

空間軸：缺料就停，料走了先拆依賴者

共效表 Σ 是有型別的部分函式：key → 值。寫入 set(k,v) 本身就是一次可拆的改動，拆法是刪掉那個 key。

一個 plugin 宣告規格 d（它要讀的 key）。掛板從 σ 變到 σ′ 時，對 d 只分三種：剛齊（開工）、剛缺（停工）、沒變（沒事）。齊了才執行 e；缺了就跑累積器。

單向排序免費：B 要的 key 由 A 提供，B 只能在 A 開工之後開工。反向要額外機器：A 卸載時先通知依賴者，等他們拆完，A 的值還留在表上。這是 §4.3.1 的 withdrawal，對應程式裡 UNLOADING 先宣告停供、再 dispose。

與 intercept 不改共用表。它們長出子掛板，丟掉子環境就夠了，沒有要追蹤的拆法。

plugin 加 fiber 才把兩軸接到整棵樹

一個 plugin 是三元組 (d, p, e)：要讀的 key、會寫的 key、開工時跑的副作用。實例叫 fiber。registry 是一棵以 root 為根的樹。共用表是所有 ACTIVE fiber 的 p 的不交聯集。同一 realm 裡兩條實例不能寫同一個 key。

§4.2 先假設轉移原子、立刻、不會失敗。§4.3 再放進真實 runtime：withdrawal、iteration、非同步、失敗。卸載一旦開始會跑完，這叫慣性。§4.4 證明保存、全域時間／空間可組合、progress、合流。

整棵樹要卸得乾，得兩邊可交換，或靠共效把卸載排好。論文沒說「任意亂改共用物件都能拆乾淨」。

Algorithm 5：refresh 重算 target。target 變了且沒有進行中轉移，才開 reload 或 unload。reload 先記下這次看到的 provider uid，再跑 apply。unload 先等依賴者拆完，再跑 dispose。uid 不重用，換了一個提供同一個值的 fiber，仍算依賴變了。

HMR 是交易：新模組 import 失敗就還原 cache，用舊組件重建 fiber，不留半套。

rhc 主線

機制

ctx.effect 把 callback 的回傳值當拆法疊進 fiber.dispose。unload 先通知依賴 fiber，再 LIFO 跑拆法。inject 是 key 集合；表一變就 refresh，決定 reload 或 unload。

前提

對共用狀態的改動都走掛板。每個 key 在一個 realm 只有一個 ACTIVE 寫者。拆法在自己剛寫完的狀態上成立。

適配

DSH 的 agent-loop、tools、llm 都是可卸載 row。rhc 若要熱換工具或模型，同一契約避免重啟丟掉 session。

不抄

不先實作 §4 演算與合流證明。不把 4000 plugin 當規模目標。HMR 交易不當第一個功能。可交換條件未證明前，不要假設可以任意交錯卸載。

詞卡

Cordis

追蹤拆法、解析依賴的 meta-framework。core 管 runtime；設定檔那層做對帳與熱替換。

時空可組合

時間：卸得乾。空間：依賴用宣告等齊，料走了要通知。

可逆副作用

每次改掛板都交出拆法。runtime 把它們疊起來，卸載依序跑。

反應式共效

plugin 宣告要的 key。掛板一變，對這份名單分成開工、停工、沒事。

inject

要等齊的 key 名單。沒齊就不會跑 apply。

isolate

同一個 key 在不同子環境解到不同值。長出子掛板，丟掉即可，不追拆法。

獨立

兩個改動可交換，且不改壞對方的拆法。交錯卸載的前提。
