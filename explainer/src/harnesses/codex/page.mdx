  <p>呼叫模型的客戶端在 <code>core/src/client.rs</code>。模型與努力程度的設定在 <code>session/reasoning_effort.rs</code> 與 <code>codex-rs/config</code>。</p>
  <H3 id="s-parts-auth" n="4">登入</H3>
  <p><code>codex login</code> 用旗標選路。沒有旗標就開瀏覽器，本機聽 <code>localhost</code>，把 ChatGPT 票寫進 <code>auth.json</code>。<code>CODEX_API_KEY</code> 不參與這次選擇，它只在之後讀憑證時蓋過檔案。</p>
  <p>寫進檔的有兩種票。<code>AuthMode::ApiKey</code> 只有 stdin 進來的金鑰。<code>AuthMode::Chatgpt</code> 是瀏覽器或 device-code 換到的 tokens。<Term k="pkce">PKCE</Term> 兩邊都用，但產生的地方不同。瀏覽器那條自己做 verifier。device-code 的 verifier 是輪詢回應給的。真正落盤的是 <code>save_auth</code>。預設 store mode 是 File，檔在 <code>$CODEX_HOME/auth.json</code>。</p>
  <p>入口在 <code>cli/src/main.rs</code>。<code>--with-api-key</code> 和 <code>--with-access-token</code> 同時出現就結束。接著才是 <code>--device-auth</code>，然後舊的 <code>--api-key</code>（只印停用），然後 <code>--with-api-key</code> 從 stdin 讀金鑰，然後 <code>--with-access-token</code>。一個都沒有，呼叫 <code>run_login_with_chatgpt</code>，進 <code>run_login_server</code>。</p>
  <p>瀏覽器那條先 <code>generate_pkce</code>，綁定 <code>127.0.0.1:1455</code>（被佔用就改 1457），redirect 是 <code>http://localhost:&#123;port&#125;/auth/callback</code>。授權網址打到 issuer 的 <code>/oauth/authorize</code>，帶 <code>code_challenge_method=S256</code>。使用者回來之後，<code>exchange_code</code> 用 <code>grant_type=authorization_code</code> 換票。接著還會用 id token 再換一次 <code>openai-api-key</code>。這次失敗仍會把 ChatGPT tokens 存下來。</p>
  <p>device-code 不聽 localhost。它 POST <code>/api/accounts/deviceauth/usercode</code>，螢幕印 <code>/codex/device</code> 與 user code，再 poll <code>/deviceauth/token</code>。404 是這台伺服器沒開裝置碼，CLI 印完就停，不改走瀏覽器。</p>

  <p><code>CODEX_API_KEY</code> 在 <code>AuthManager</code> 讀憑證時優先，做成記憶體裡的 <code>CodexAuth::ApiKey</code>，不寫 <code>auth.json</code>。<code>codex login status</code> 把這個開關關掉，所以 status 看不到只活在環境變數裡的 key。Keyring 模式成功之後會刪掉 <code>auth.json</code>。一般預設是 File。device-code 存下來的 <code>openai_api_key</code> 是空的。localhost 那條才多打一次 token-exchange。</p>
